# 游戏策划AI文档助手 v2.2 修复与增强方案

## 概述

针对 v2.1.0 的三个 bug 修复、UI 美化（含夜间模式）及两个新增功能。

## 1. Bug 修复

### 1.1 配置表"另存为"无反应

**问题：** 右键配置表分类的 Excel 文档 → 另存为 → 无任何反馈。

**根因：** `HomePage.vue:handleDocCommand('saveAs')` 中 Excel 分支存在多处静默失败：
- `excel.saveToFile()` 返回 `null` 时无 else 分支，无提示退出
- `excel.loadExcelData()` 在文档 `path` 为空时静默返回，导致 `excelData` 为 null
- 用户得不到任何视觉/文字反馈

**修复：**
- `saveToFile` 返回 null 时增加 `ElMessage.error('文件保存失败')`
- `handleDocCommand` 中增加 loading 状态，防止重复点击
- 统一 saveAs 流程：确保文档加载 → excel 数据就绪 → 保存 → 结果反馈 每一步都有明确状态提示

**涉及文件：** `src/pages/HomePage.vue`、`src/composables/useExcel.ts`

### 1.2 职业角色显示

**问题：** 设置 → 职业角色 标签页，职业下拉列表为空或无法正确显示对应 Prompt。

**根因：** `settings.openSettings()` 仅执行 `loadConfig()`，未调用 `prompts.loadProfessionsFull()`，导致 `professionsFull` 数据未加载。

**修复：**
- `useSettings.ts` 中 `openSettings()` 改为 async，先等待 `loadProfessionsFull()` 完成再显示对话框
- `HomePage.vue` 中 `settings.openSettings()` 调用处改为 await

**涉及文件：** `src/composables/useSettings.ts`、`src/pages/HomePage.vue`

### 2.2 实现方式

1. **CSS 变量驱动** — 在 `style.css` 中定义 CSS 变量，浅色/夜间模式通过 `:root` / `[data-theme="dark"]` 切换
2. **useTheme.ts** — 新的 composable，管理主题状态、持久化到 config.json
3. **设置开关** — SettingsDialog.vue 通用设置 tab 添加「夜间模式」切换开关
4. **逐步替换** — 将 HomePage.vue 和各 dialog 中的硬编码 Tailwind 颜色 class（如 `bg-zinc-50` `text-zinc-900`）逐步替换为 CSS 变量绑定
5. **electron 窗口适配** — 夜间模式时同步更新 `BrowserWindow` 的 `backgroundColor`

## 4. 知识库向量块大小区间值

### 4.1 前端改造

当前：`<el-input-number v-model="chunkSize" :min="100" :max="500" :step="50" />`

改为：
```
最小值：<el-input-number v-model="chunkSizeMin" :min="50" :max="500" :step="50" />
最大值：<el-input-number v-model="chunkSizeMax" :min="100" :max="1000" :step="50" />
```

`KBDialog.vue` 中 prop: `chunkSize` → `chunkSizeMin` + `chunkSizeMax`
`useKnowledgeBase.ts` 中 `chunkSize` → `chunkSizeMin` + `chunkSizeMax`

### 4.2 后端改造

**API: `POST /api/kb/chunk-size`**
- 请求体：`{"min": 100, "max": 500}`
- 保存到 `config.json` 为 `{"chunk_size_min": 100, "chunk_size_max": 500}`

**API: `POST /api/kb/rechunk`**
- 触发知识库对已有所有文档重新分块 + 重新向量化
- 读取 config 中的 `chunk_size_min` / `chunk_size_max`
- 对每个文档的原始内容，按新区间重新分块
- 清除旧向量，重新编码，保存

**KnowledgeBase 类改造：**
- `_chunk_tokens` (int) → `_chunk_size_min` / `_chunk_size_max` (int, int)
- `_chunk_text_tokens()` 增加区间参数，每块随机取 `random.randint(min, max)`
- 新增 `rechunk_all()` 方法
- 需要持久化每个文档的原始内容（修复当前 chunks.json 不保留原文的问题）

### 4.3 数据持久化

当前 chunks.json 只存分块后的片段，不存原文。需要新增 `raw_contents` 字段或额外文件来存储原始文档内容，以支持重新分块。

方案：在 `chunks.json` 中增加顶层字段 `raw_docs`：
```json
{
  "raw_docs": [
    {"file_hash": "...", "filename": "...", "content": "原始全文...", "doc_type": "docx", "file_size": 1234}
  ],
  "chunks": [...]
}
```

### 4.4 涉及文件
- `src/components/dialogs/KBDialog.vue` — 区间输入 UI
- `src/composables/useKnowledgeBase.ts` — 区间值状态
- `api/routers/knowledge_base.py` — 新增 rechunk 接口
- `api/knowledge_base.py` — KnowledgeBase 类改造
